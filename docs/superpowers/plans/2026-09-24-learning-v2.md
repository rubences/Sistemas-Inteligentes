# Learning workspace v2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver all approved learning-workspace improvements and a tested optional class service.
**Architecture:** Static campus modules with an isolated Python runtime; separate authenticated Python/SQLite service for shared records.
**Tech Stack:** HTML/CSS/JavaScript, Pyodide 314.0.7, Python standard library, SQLite.
**Spec:** docs/superpowers/specs/2026-09-24-learning-v2.md

## Global constraints

Preserve all 12 canonical HTML/PDF hashes. English learning content. Relative paths beneath the GitHub project URL. Import old progress. Treat learner content as text. No credentials, records or official solutions in the public repository. Browser code execution is formative. Public deployment of the class server needs a supplied hosting destination.

## Review focus

- A full Unicode/code backup must be restorable without losing previous data on an invalid import.
- Navigation and reload must not discard the latest typed evidence or code.
- Cancelling or leaving a Python run must terminate work and allow another run.
- A student's token must not access another room's records or any teacher endpoint.
- Algorithm comparisons must use the same instance/budget and separate timeout, training and evaluation results.

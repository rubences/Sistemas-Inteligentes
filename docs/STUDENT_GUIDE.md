# Student guide

## A productive study cycle

1. Read the unit's learning outcomes. Write down what you can already explain.
2. Open the presentation. Use **Study mode** for continuous reading and **Notes** for additional explanation.
3. Before touching a laboratory control, write a prediction.
4. Change one variable, run the experiment, and record the settings and outcome.
5. Explain why the observation follows from the model. Add a condition under which it might fail.
6. Complete the self-check, read every explanation, then implement the unit's programming exercise.

## Presentation controls

Use the visible Previous/Next buttons or the left/right arrow keys. **I** opens the index, **N** the notes, **E** study mode and **F** full screen. Keyboard shortcuts do not replace typing inside form controls. On narrow screens presentations open in study mode. Exit full screen with Escape. The PDF is a static study version: experiments run in the HTML presentation.

## Laboratory evidence

In the campus, choose **Laboratories → Workspace**. The experiment appears beside your evidence form. Record a prediction, settings, result, explanation and limitation; notes save as you type. Use the hosted campus or local HTTP server for the integrated layout. A standalone laboratory link remains available. A completion tick requires nonempty evidence, but does not judge the quality of the explanation.

Work in pairs when possible: one operator and one observer. Swap roles between trials. A screenshot can illustrate a result, but cannot replace the settings and your reasoning. Download your evidence report and submit it through the channel selected by your instructor.

## Keeping your work

Evidence, code, challenge records, reviewed-unit ticks and self-check answers stay in this browser. They are sent to the instructor only when you explicitly submit an evidence preview through a configured live room; otherwise use Moodle. Use **Resources → Export progress** regularly. On another device, choose **Import progress**; importing replaces that browser's saved record after confirmation. Preserve a backup first.

Private browsing, clearing site data or moving the site to another address can remove or separate saved work. A local file and a hosted site have different storage locations. Some browsers restrict storage for local files; the campus shows a notice if storage fails. You can still export the current session.

## Programming

Choose **Programming** to edit and run an exercise in the browser. Public checks, hints and a worked example are available for each unit. Code saves as you type. **Stop** cancels execution; an automatic ten-second limit prevents a runaway loop. Loading the pinned Python runtime requires network access. Public checks are practice feedback, not secure grading.

For local development, read [the exercise contracts](PRACTICE.md). Run the reference tests to confirm your environment, implement `practice/python/student.py`, then run `check_student.py`. The starter fails by design. Passing the public tests is a starting point: add an edge case and defend the algorithm's assumptions.

For the [Loopover project](CAPSTONE.md), count a coupled row-then-column action as **one** step. Reversing only the direction while preserving phase order is generally not the inverse.

## If something looks wrong

Reload a downloaded, fully extracted copy. Open `index.html`, not the GitHub source preview. On a small screen use the Menu button. If a simulation result seems inconsistent, record the unit, slide, parameters, action sequence and browser. Report those details to the instructor or in a repository issue.

## Challenges and targeted review

Use each unit’s three challenge levels: foundation, applied and extension. Record evidence before marking a challenge ready. Download your report for feedback. **Concept review** prioritizes ideas you answered incorrectly, then correct answers older than seven days. Unanswered ideas remain unassessed. **Search course** finds slide text and explanations; **Read & understand** pairs a slide with its notes. The glossary supplies English and Spanish terminology.

## Live participation

If your instructor has deployed the optional service, open **Shared classroom**, enter its HTTPS address, invite code and a pseudonym. You can replace a poll response while the question is open. Edit the evidence preview before submitting; drafts save for this browser session and return when you resume. Use **Download this draft** for a durable copy. A submission allows 60,000 characters; longer reports remain intact for selection or upload through Moodle. Keep the receipt. Feedback appears in the same view, which refreshes every ten seconds. Reload and choose **Resume student session** to reconnect in the same tab. Closing the browser session may remove the token; the instructor still retains submitted records. Do not include information unrelated to the course.

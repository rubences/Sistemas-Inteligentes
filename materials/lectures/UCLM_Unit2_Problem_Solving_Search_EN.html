Search tree

S / A / X

States describe configurations. Nodes describe paths that reach configurations.

Adapted from the supplied Unit 2 material09 / 53
Teaching and study notes

A state-space graph may be given explicitly or generated through a successor function. A search tree unfolds paths, so repeated states may appear many times. Do not equate the number of search nodes with the number of distinct states. If a cycle returns to S, tree search may produce infinitely many path nodes even when the graph is finite.

Search mechanics

A generic tree-search skeleton

frontier ← [root(initial_state)]
while frontier is not empty:
    node ← remove_next(frontier)
    if goal(node.state):
        return reconstruct(node)
    for (action, state, cost) in successors(node.state):
        child ← Node(state, node, action,
                     node.depth + 1, node.g + cost)
        insert(frontier, child)
return FAILURE

The removal rule controls search order. Duplicate handling adds another design decision.

Teaching and study notes

This is explanatory pseudocode, not a finished Java implementation. It may revisit the same state arbitrarily many times. The root has depth and cost zero and no parent. A returned node encodes a path that must be reconstructed. The goal test is deliberately placed after frontier removal so later UCS discussion uses a consistent convention.

FIFO
queue

Insert new nodes at the back.
Remove the oldest node at the front.

Expansion order

All depth-0 nodes, then depth-1 nodes, then depth-2 nodes, and so on.

What it optimizes

The number of actions. This also minimizes cost when every action costs the same.

Teaching and study notes

FIFO means first in, first out. A queue stores nodes, not just state labels, when paths must be reconstructed. Specify successor order before asking for a trace. On finite graphs, marking states when enqueued avoids unnecessary duplicate frontier entries. The first goal found has minimum depth. Unequal costs remove the general cost-optimality guarantee.

Supplied material · Complexity conventions clarified17 / 53
Teaching and study notes

For an implicit search tree, complexity is expressed using branching and solution depth. With our goal test on removal, nodes one level below depth d may already have been generated, yielding a conservative O(b^(d+1)) time and memory bound. Adapted from the supplied Unit 2 material19 / 53
Teaching and study notes

Uniform-cost search is a goal-directed version of Dijkstra-style shortest-path exploration with suitable costs. A priority queue may support decrease-key, or it may contain a new entry while the old one is later skipped as stale. The simulator uses the latter approach. Equal positive step costs make cost order agree with depth order, apart from tie-breaking.

Uniform-cost search

Best costs and stale entries

best[start] ← 0; push(root, priority=0)
while frontier is not empty:
    n ← pop_min_g()
    if n.g != best[n.state]: continue
    if goal(n.state): return reconstruct(n)
    for (a, s, cost) in successors(n.state):
        new_g ← n.g + cost
        if new_g < best.get(s, infinity):
            best[s] ← new_g
            push(Node(s, n, a, new_g), priority=new_g)
return FAILURE

The goal test follows stale-entry rejection and minimum-cost selection.

Adapted from the supplied Unit 2 material20 / 53
Teaching and study notes

This is abbreviated pseudocode. A real node also records depth and any deterministic tie-break identifier. best is keyed by immutable state. With nonnegative edge costs, a non-stale node removed at minimum g has settled optimal cost. With strictly positive lower-bounded costs and finite branching, UCS is also complete for finite-cost solutions in the usual infinite-tree setting. Do not copy a discovered-state boolean from BFS into this algorithm.

Depth limits

Depth-limited search has three outcomes

SOLUTIONA goal was found within the limit.
CUTOFFA potentially useful branch was stopped by the limit.
FAILUREAll available branches were exhausted without finding a goal or being cut off.

CUTOFF means “the limit prevented a conclusion”, not “there is no solution”.

Adapted from the supplied Unit 2 material26 / 53
Teaching and study notes

Let the depth limit be ℓ. DLS explores depth-first but stops beyond ℓ. If a goal lies deeper, the search may return cutoff. Distinguish that result from genuine failure, because IDS must continue after cutoff. The demonstration recognizes terminal dead ends as failure even when they occur at the depth limit. This is a slightly more informative version of the common textbook rule that returns cutoff immediately at the bound.

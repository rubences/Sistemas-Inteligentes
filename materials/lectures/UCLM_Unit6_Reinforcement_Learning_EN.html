MDP

An MDP defines a sequential decision problem

ElementDefinition in this unit
S, A(s)States and legal actions in each state.
P(s′ | s,a)Probability of the next state after an action.
R(s,a,s′)Expected immediate reward for that transition.
γ and start distributionDiscount factor and where episodes begin.
Terminal statesStates after which no further task rewards occur.

The policy π is what we evaluate or improve; it is separate from the environment model.

Adapted and expanded from the supplied Unit 6 material06 / 60
Teaching and study notes

A common MDP tuple is (S,A,P,R,γ). We additionally state the initial-state distribution and terminal convention because they affect experiments. When rewards are stochastic, R may be an expectation or the joint distribution p(s′,r|s,a) may be used. Our gridworld rewards are deterministic once the next cell is known.

Policy

A policy specifies the agent’s choices

Deterministic

a = π(s)

Each state selects one action.

Stochastic

π(a | s)

Each state defines a probability distribution over legal actions.

For every state, probabilities must be nonnegative and sum to 1.

Adapted and expanded from the supplied Unit 6 material09 / 60
Teaching and study notes

A stochastic policy can implement exploration, represent uncertainty in action preferences, or be required by a problem setting. In a finite discounted fully observed MDP, a deterministic stationary optimal policy exists. That statement does not extend automatically to partially observed or multi-agent settings. Stationary means the rule does not depend explicitly on time, provided the state already contains required task information.

Objective

Return accumulates rewards over time

Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + …
RewardThe immediate signal from one transition.
ReturnThe discounted total along a trajectory.
ObjectiveMaximize expected return under the chosen start distribution.

Adapted and expanded from the supplied Unit 6 material10 / 60
Teaching and study notes

This unit focuses on expected discounted return. Other objectives include average reward, constrained return and risk-sensitive criteria. The first reward receives discount exponent zero. The random return of a sampled trajectory and its expectation are different quantities. A value function estimates the latter.

Horizon

Discounting and termination solve different problems

Continuing task

For bounded rewards and γ<1, the discounted infinite sum is finite.

|Gₜ| ≤ Rmax / (1−γ)

Episodic task

Return stops at a task terminal. γ=1 can be valid when returns are well defined.

A small γ changes preferences over timing. It does not make the task end sooner.

Adapted and expanded from the supplied Unit 6 material13 / 60
Teaching and study notes

For episodic undiscounted problems, termination alone is not enough if episode lengths or total rewards have an infinite expectation. A finite horizon and bounded rewards suffice. A common rough scale 1/(1−γ) describes discounted weight, not a guaranteed planning depth. γ=0 retains only the immediate reward.

Optional extension

Potential-based shaping can preserve optimal choices

R′ = R + γΦ(s′) − Φ(s)

Idea

Add progress information through a state potential Φ.

Boundary convention

Use the same γ. For a stopped episodic return, set terminal potentials to 0.

The added discounted rewards telescope to −Φ(s₀), independent of the actions taken.

Ng, Harada & Russell (1999), Policy invariance under reward transformations15 / 60
Teaching and study notes

For bounded potentials with γ<1, the infinite discounted boundary term vanishes. In an episodic sum, zero terminal potential removes the final boundary term. Then return shifts by a state-dependent constant and optimal action preferences are preserved. Arbitrary bonuses lack this guarantee. This preserves the objective, not a guarantee of faster learning.

Value functions

V evaluates a state; Q evaluates an action in a state

Vπ(s) = Eπ[Gₜ | Sₜ=s]
Qπ(s,a) = Eπ[Gₜ | Sₜ=s, Aₜ=a]

Q fixes the first action, then follows π. V averages over the policy’s first action.

Adapted and expanded from the supplied Unit 6 material16 / 60
Teaching and study notes

For a stochastic policy, Vπ(s)=Σa π(a|s)Qπ(s,a). The policy is part of the definition: a state has different values under different continuation behaviours. A greedy action with respect to an inaccurate Q estimate is not necessarily truly optimal. Terminal V is zero under our reward-on-entry convention.

Bellman expectation

A fixed policy averages over actions and outcomes

Vπ(s) = Σₐ π(a|s) Σₛ′ P(s′|s,a)
[R(s,a,s′) + γVπ(s′)]

Prediction asks how good the specified policy is.

Source Bellman expectation · Expanded finite-state notation17 / 60
Teaching and study notes

This expression uses expected reward conditional on the state transition. Each transition probability multiplies both immediate reward and discounted successor value. If the policy is deterministic, the outer sum reduces to the selected action. The successor terminal value is zero; no future reward is counted after termination.

Bellman optimality

Control selects an action before averaging its outcomes

V*(s) = maxₐ Σₛ′ P(s′|s,a)
[R(s,a,s′) + γV*(s′)]

The agent chooses the action. The environment samples its consequence.

Adapted and expanded from the supplied Unit 6 material18 / 60
Teaching and study notes

The maximum is outside the sum over successor states because the action must be selected before the random outcome is observed. Moving max inside that sum would often give the agent impossible knowledge of future randomness. This connects to Unit 5: a stochastic environment uses an expectation, whereas a strategic adversary requires an opponent model.

Dynamic programming

Value iteration repeatedly applies optimality backups

V[s] = 0 for every state
repeat:
    old = copy(V)
    for each nonterminal state s:
        V[s] = max_a Σ_s′ P(s′|s,a) * (R + γ*old[s′])
    Δ = max_s |V[s] - old[s]|

Synchronous sweeps use the previous vector for every state in the next vector.

Source dynamic programming · Berkeley CS188, Value iteration20 / 60
Teaching and study notes

With finite states and actions, bounded rewards and γ<1, the Bellman optimality operator is a contraction. Its fixed point is unique and value iteration converges to it. An in-place implementation can also work under appropriate conditions, but its intermediate sweeps differ. Our lab uses synchronous updates to make propagation visible. Known-model dynamic programming is a planning method.

Policy iteration

Evaluation and improvement can be separated

01Evaluate πSolve or iterate the Bellman expectation equations.
02Improve πChoose actions greedy with respect to the evaluated values.
03RepeatStop when the policy no longer changes.

Policy evaluation follows the current policy. Policy improvement asks whether another action is better.

Adapted and expanded from the supplied Unit 6 material22 / 60
Teaching and study notes

Exact policy iteration in a finite discounted MDP reaches an optimal policy under consistent tie handling. Modified policy iteration uses incomplete evaluation. Value iteration combines a short evaluation-like backup and greedy improvement in each sweep. These are model-based planning procedures; learning a model first creates a model-based RL system.

Monte Carlo

A complete episode provides a sampled return

follow a fixed policy π until termination
compute G backward through the episode
for each state on its first visit in the episode:
    N[s] += 1
    V[s] += (G_at_that_visit - V[s]) / N[s]

First-visit Monte Carlo averages one return per visited state per episode.

Source Monte Carlo route · Explicit first-visit estimator24 / 60
Teaching and study notes

Every-visit Monte Carlo uses every visit instead and is a different estimator. Here first-visit means first occurrence in forward time, even when returns are computed backward. No transition model and no bootstrapped next-state value are required. A truly continuing task needs another construction because there is no complete episode to wait for.

TD(0) prediction evaluates the policy generating the sampled transitions under the usual assumptions. Q-learning uses a greedy continuation target

Q(s,a) ← Q(s,a) + α[r + γ maxₐ′Q(s′,a′) − Q(s,a)]

Behaviour

The agent can explore while collecting transitions.

Target

The update uses the largest current next-state action value.

Q-learning is off-policy: the target can differ from the action actually selected next.

Adapted and expanded from the supplied Unit 6 material29 / 60
Teaching and study notes

For a true terminal successor, the target is just r. In the tabular setting, Q-learning can converge to Q* under appropriate exploration and learning-rate conditions, described later. Finite training, constant α and nonlinear function approximation do not inherit that guarantee automatically. The maximum ranges over legal next actions only.

SARSA

SARSA includes the selected next action

Q(s,a) ← Q(s,a) + α[r + γQ(s′,a′) − Q(s,a)]
Five quantitiesState, action, reward, next state, next action.
On-policyThe next action comes from the behaviour policy being learned.

If exploration selects a poor next action, that action affects this SARSA target.

Adapted and expanded from the supplied Unit 6 material30 / 60
Teaching and study notes

The next action must be sampled before the nonterminal SARSA update and then carried forward as the action actually used. Do not sample one next action for the update and silently execute another. At a terminal successor no next action is needed. SARSA learns values appropriate to the ongoing behaviour, including its exploratory actions.

Implementation

A Q-learning loop needs two stopping decisions

s = env.reset()
while collecting data:
    a = epsilon_greedy(Q[s])
    s_next, r, terminated, truncated = env.step(a)
    target = r if terminated else r + γ*max(Q[s_next])
    Q[s,a] += α * (target - Q[s,a])
    s = env.reset() if (terminated or truncated) else s_next

Reset after either ending signal. Remove continuation only for true termination.

Source Q-learning pseudocode · Farama, Handling time limits35 / 60
Teaching and study notes

This is pedagogical pseudocode, not a copy of a particular API signature. A vectorized or auto-reset environment must expose the actual final observation for the bootstrap target; using a fresh reset state is incorrect. Legal-action restrictions must also apply to max Q. For SARSA, choose the next behaviour action and use its value, including at a nonterminal external cutoff.

Convergence

Tabular Q-learning guarantees need conditions

Stable finite MDPFinite state-action table, stationary dynamics and bounded rewards.
Discounted settingUse γ<1 for the standard discounted theorem.
CoverageVisit every relevant state-action pair infinitely often.
Learning ratesFor each pair: Σαₙ=∞ and Σαₙ²<∞.

A finite classroom run with constant α illustrates learning; it does not satisfy an asymptotic theorem.

Watkins & Dayan (1992), Q-learning39 / 60
Teaching and study notes

Watkins and Dayan prove a tabular convergence result. The conditions are sufficient assumptions, not a practical finite-sample certificate. αn=1/n for the nth visit to a pair satisfies the two sum conditions. A constant positive α does not satisfy the squared-sum condition. A neural Q-function introduces a different approximation problem.

Debugging workshop

Two plausible lines can create a silent learning error

next_state, reward, terminated, truncated = env.step(action)
done = terminated or truncated
if done:
    next_state = env.reset()
target = reward + γ * (1 - done) * max(Q[next_state])
Q[state, action] += α * (target - Q[state, action])

Identify the meaning of the bootstrap mask and which observation belongs in the target.

Adapted and expanded from the supplied Unit 6 material56 / 60
Teaching and study notes

There are two distinct conceptual errors. First, done combines termination with external truncation and therefore removes valid continuation at truncation. Second, overwriting the final next state before the update loses the observation needed for bootstrapping. With this exact mask the second error is concealed when done is true; fixing only the mask would expose it.

UCLMUniversidad de Castilla-La Mancha
Debugging solution

The update uses the final transition before resetting

final_state, reward, terminated, truncated = env.step(action)
if terminated:
    target = reward
else:
    target = reward + γ * max(Q[final_state])
Q[state, action] += α * (target - Q[state, action])
state = env.reset() if (terminated or truncated) else final_state

Also check legal actions, reward timing, random seeds and evaluation without learning.

The relative weight of later rewards, hence the objective.

Function, program and architecture

f : P* → A

P*: all finite percept histories.
A: the set of possible actions.

The function specifies an action for each history.

FunctionAn abstract description of behaviour.
ProgramAn implementation that computes an action.
ArchitectureThe platform that runs the program and connects inputs and outputs.

Agent = architecture + program

Adapted from the supplied course material08 / 48
Teaching and study notes

The same vacuum rule can run in a simulator or a physical robot. The agent function describes behaviour, while the program realizes that behaviour. P* includes histories of different lengths. A program can summarize the past in memory rather than store every percept. For randomized behaviour, a more general description returns a probability distribution over actions. Do not confuse agent architecture with neural network architecture.

DimensionQuestionDesign implication
ObservabilityCan I observe all relevant state information?Missing information may call for memory or inference.

Supplied material · CS188, Agents22 / 48
Teaching and study notes

Unknown dynamics and partial observability are different. We can know the laws of a world while being unable to see its state, or see the state without knowing how actions affect it. Determinism refers to a fully specified state and, where relevant, the actions of all agents. Not knowing an opponent’s choice does not imply that the game rules are random.

Supplied material · Conceptual clarifications23 / 48
Teaching and study notes

Discrete does not necessarily mean finite. In a semidynamic setting, the relevant world does not change while the agent deliberates, but performance may change with time. In timed chess, the pieces remain fixed during a player’s turn while the clock runs down. Episodic means that a decision does not affect later tasks within the model, not merely that a task has an ending.

Six questions to check understanding

01

What does P* represent?

All finite percept histories, not just the current percept.
02

Can a rational decision fail?

Yes. It is assessed by expected performance given the available information.
03

Does unknown mean partially observable?

No. Unknown rules and hidden state are different difficulties.
04

Must a goal-based agent learn?

Not necessarily. It may plan with a supplied model.
05

What does utility add to a goal?

It compares the quality of different acceptable outcomes.
06

How many phases does 02+ have?

Two: row 0 right, then column 2 down. Together they count as one action.

Misconceptions we can now correct

Incomplete or incorrect claimCorrection
“Success proves rationality.”Evaluate the choice using information available before the outcome.
“Every agent needs an LLM.”Rules, search and other methods also implement agents.
“Learning means remembering.”Storing information does not necessarily improve a rule or model.
“All discrete spaces are finite.”A discrete set may be countably infinite.
“A goal is enough to compare plans.”A goal tests achievement. Cost or utility compares alternatives.
